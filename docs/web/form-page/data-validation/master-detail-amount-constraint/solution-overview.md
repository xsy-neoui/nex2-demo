# 方案介绍

## 方案概述

本方案通过在表单页面（EntityForm）中进行组件级扩展实现。在表单提交前，通过扩展脚本对主表与子表数据进行逻辑校验：一方面校验子表中数量字段是否为空或为 0；另一方面计算子表中所有明细的金额合计，并与主表的总金额字段进行比对，防止提交超出预算上限的数据。若校验不通过，系统将在前端提示用户并阻止表单提交。该方案基于 Nex 页面扩展机制实现，无需调整标准表单结构，即可灵活地在业务层实现主子表约束控制逻辑。

## 扩展组件

|终端|扩展对象|扩展页面|扩展区域|扩展组件|扩展功能|
|---|----|----|----|----|----|
|网页端/移动端|采购申请单|表单页|表单底部按钮|保存按钮|增加保存前事件，校验主表与子表金额一致性及其他约束规则|

## 功能设计

1.  **触发时机**

    当用户单击“保存”按钮时触发校验逻辑。

    若校验未通过，系统在前端进行提示并阻止保存操作。

2.  **校验逻辑**
    -   **子表数据有效性校验**

        遍历子表中的每一条明细记录，检查“数量”字段是否为空或等于 0。

        若存在不合法记录，则中止保存流程，并提示用户“采购数量必须是大于0的数字”。

        **金额约束校验**

        汇总子表中所有明细的“金额”字段求和。

        获取主表的“总金额限制”字段的值。

        若子表金额合计 &gt; 主表总金额限制，则提示用户“子表金额合计超出总金额限制，无法提交”，并终止保存操作。

    -   **校验通过处理**

        若所有校验均通过，则允许保存数据。
