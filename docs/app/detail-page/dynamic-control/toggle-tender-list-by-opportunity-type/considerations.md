# 注意事项与最佳实践
1.  **确认事件触发时机**

    在详情页扩展中，动态控制组件的逻辑应在页面渲染完成后执行（使用 afterRender 事件）。此时所有组件实例已加载完毕，可安全访问组件和数据实例。若在渲染前执行，可能导致 event.cmp 或 props.getInstance\(\) 无法获取。

2.  **明确相关列表的唯一标识**

    在 relatedList 中，相关列表的唯一标识需要由实体 ApiKey 与关联字段 ApiKey 组合而成（例如：\{objectApiKey: "tenderInfo\_\_c", relatedItemApiKey: "opportunity\_\_c"\}）。此组合用于唯一确定页面上的目标相关列表，避免误控制其他列表组件。

3.  **合理使用字段判断逻辑**

    在判断条件（如 detailData\['opportunityType\_\_c'\] == 1）时，应确保字段 API 名称与数据类型准确无误。若字段返回枚举值或字符串，应匹配对应值类型，避免逻辑失效。

4.  **处理数据加载延迟**

    若详情数据通过异步方式加载（例如需等待接口返回），应在确认数据加载完成后再执行逻辑。必要时可在 afterRender 中加入延时或检查机制，以防止 detailData 为空导致判断失效。

5.  **提示与调试日志**

    在开发阶段可通过 ctx.util.log\(\) 输出关键信息（如 detailData 值、判断条件结果等），便于问题定位。生产环境中应删除或禁用调试日志，保持页面性能。

6.  **考虑扩展的兼容性**

    若页面中存在多个相关列表或复杂嵌套组件，需确保控制逻辑仅作用于目标组件，避免影响其他模块显示。

7.  **测试覆盖多类型数据**

    应测试不同商机类型（招标 / 非招标）的页面表现，验证在不同数据组合下“招标信息”列表是否正确显示或隐藏。

8.  **保持扩展代码可维护性**

    建议将控制逻辑封装为独立函数（如 toggleTenderListVisibility\(detailData, cmp\)），以提升代码复用性和可读性，便于后期扩展更多控制条件。
