# 注意事项与最佳实践
1.  **子表数据完整性校验**

    在进行主子表校验时，应确保遍历子表的每条记录，包括新增、更新和删除的数据。避免遗漏子表明细，导致逻辑校验失效。通过 create 和 update 数组进行有效遍历，确保所有子表数据都能参与校验。

2.  **金额与数量约束逻辑**

    在校验金额或数量时，应确保字段类型与精度正确，避免因空值或浮点数误差导致校验结果不准确。可以使用 Number\(\) 转换字段值，确保进行数字运算时不产生非预期结果。提示信息应清晰明了，帮助用户理解问题所在。

3.  **前端拦截与用户提示**

    在 beforeSave 事件中，及时拦截不合规数据并阻止表单保存，避免不符合条件的数据提交。通过清晰的提示框告知用户错误原因，如“采购数量必须是大于0 的数字”，避免无效提交。

4.  **与后端一致性校验**

    前端校验是第一道防线，但为保证数据的完整性与安全性，必须结合后端进行二次校验，避免绕过或前后端逻辑差异，确保数据一致性。

5.  动态表单/明细变化监听

    若表单中字段或子表明细支持动态增删改，应确保每次数据变化时都触发校验逻辑，以保证页面展示与约束逻辑始终一致，避免用户未修改内容时数据仍然无效提交。

6.  **合适的提示信息设计**

    提示信息不仅要简洁明了，还应具体说明错误原因，例如“子表金额合计超出预算金额”而不是仅仅显示“金额错误”。帮助用户更高效地找到并修正问题。
